## 2.1.1. Introduction

Principal component analysis (PCA) is a widely used method for summarising patterns of genetic variation among individuals.

Genomic datasets may contain hundreds of thousands or millions of variable sites. PCA reduces this high-dimensional dataset to a much smaller number of axes, called **principal components (PCs)**.

Each principal component describes an independent axis of variation among individuals. The first principal component explains the greatest amount of variation in the dataset, the second explains the greatest amount of the remaining variation, and so on.

In population genetic datasets, PCA is commonly used to identify:

- broad-scale population structure;
- genetic differentiation among sampling locations or populations;
- clusters of genetically similar individuals;
- admixed or intermediate individuals;
- finer-scale genetic structure within previously identified groups.

In this tutorial, we will begin with a VCF file, convert it to PLINK format, remove variants in strong linkage disequilibrium, perform PCA, and visualise the results. We will then repeat the PCA using a subset of individuals to investigate finer-scale patterns of genetic variation.

## 2.1.3. Converting the VCF to PLINK format

PLINK is a powerful command-line tool for managing and analysing large-scale genetic and genomic datasets. It was originally developed for human genetic studies, but many of its functions are broadly useful in population and evolutionary genetics. PLINK can be used to convert between file formats, filter individuals and variants, calculate summary statistics, assess linkage disequilibrium, perform principal component analysis (PCA), and carry out a wide range of other genetic analyses.

PLINK works efficiently with its own binary file format.

A PLINK dataset normally consists of three files:

```text
.bed
.bim
.fam
```

**What do these files contain?**

The `.bed` file contains the genotype data in binary format.

The `.bim` file contains information about each variant, including chromosome, variant identifier, position, and alleles.

The `.fam` file contains information about each individual.

Convert the VCF using the command ```plink --vcf <name of vcf file> --make-bed --out <name of output file> --double-id --allow-extra-chr --set-missing-var-ids @:#```:

- The ```--double-id``` option tells PLINK not to split the sample names if they include underscores ```_```. This is sometimes used when parent-offspring relationships are encoded into sample IDs.
- ```--allow-extra-chr``` is used because we have more contigs than the program is expecting. This is because it was originally built for human data.
- The `--set-missing-var-ids` gives each variant a unique ID that is a combination of the contig and bp position. This is done by simply combining these from the VCF to give `contig:position`.

```bash
plink --vcf 108_littorina_10000contigs.vcf.gz --make-bed --out data --double-id --allow-extra-chr --set-missing-var-ids @:#
```

This should produce:

```text
data.bed
data.bim
data.fam
```

You can check this with:

```bash

```

You can inspect the `.fam` file using:

And the `.bim` file using:


## 2.1.4. Pruning variants from the VCF prior to PCA

Nearby genetic variants are often correlated because they tend to be inherited together. This correlation is called **linkage disequilibrium (LD)**.

If many strongly linked SNPs are included in a PCA, genomic regions containing large numbers of correlated variants can disproportionately influence the analysis.

For population genetic PCA, we therefore commonly select a subset of approximately independent variants using a technique called **LD pruning**.

PLINK can identify variants in strong LD using the `--indep-pairwise` command.

For example:

```bash
plink --bfile data --indep-pairwise 50 5 0.2 --out data_ld --allow-extra-chr
```

Here:

- `50` is the size of the sliding window in SNPs;
- `5` is the number of SNPs by which the window moves;
- `0.2` is the $r^2$ threshold used to identify strongly correlated variants.

PLINK produces two files:

```text
data_ld.prune.in
data_ld.prune.out
```

- `data_ld.prune.in` contains the variants retained after LD pruning.
- `data_ld.prune.out` contains the variants excluded.

We can now create a dataset containing only the retained variants:

```bash
plink --bfile data --extract data_ld.prune.in --make-bed --out data_pruned --allow-extra-chr
```

## 2.1.5. Performing PCA

The next step is to perform the actual PCA using the LD-pruned dataset. Of course, this is another analysis that we do in PLINK. 

Run:

```bash
plink --bfile data_pruned --pca 30 --out data_pca --allow-extra-chr
```

Here, `--pca 30` asks PLINK to calculate the first 30 principal components.

PLINK produces two important files:

```text
data_pca.eigenvec
data_pca.eigenval
```

## 2.1.6. Eigenvectors and eigenvalues

### Eigenvectors

The `.eigenvec` file contains the position of each individual along each principal component.

Inspect the file:

```bash
head data_pca.eigenvec
```

It will contain columns corresponding approximately to:

```text
FID IID PC1 PC2 PC3 PC4 ...
```

Each row represents an individual.

The values for `PC1`, `PC2`, and so on are the individual's **principal component scores**.

These values are what we use when producing a PCA scatter plot.

### Eigenvalues

The `.eigenval` file contains the **eigenvalue** associated with each principal component.

Inspect it using:

```bash
cat data_pca.eigenval
```

Each eigenvalue describes how much variation is associated with that principal component.

The first line corresponds to PC1, the second to PC2, and so on.

Eigenvalues tell us how much of the genetic variation in the dataset is represented by each principal component. A larger eigenvalue therefore means that the corresponding PC captures more of the variation among individuals.

It is often more intuitive to express this as the percentage of variation explained by each PC.

If the eigenvalues are $\lambda_1, \lambda_2, \lambda_3, \ldots$, the percentage of variation explained by PC1 is:

$$
[\frac{\lambda_1}{\sum_i \lambda_i} \times 100]
$$

These values could be calculated in R or Python, but being in a Unix terminal, let's leverage an `awk` command:

``` bash
awk '
# Store each eigenvalue in an array and add it to the running total
{value[NR]=$1; total+=$1}

# After all lines in the file have been read
END {

    # Loop through each stored eigenvalue
    for (i=1; i<=NR; i++)

        # Print the PC number and the percentage of variation explained
        print "PC" i, value[i] / total * 100

# Apply the awk commands to the eigenvalue file
}' data_pca.eigenval
```

## 2.1.9. Broad-scale and fine-scale population structure

The PCA above summarises variation across **all individuals** in the dataset, which in our case includes some rather divergent species.

When strongly differentiated groups are present, the first few PCs may primarily describe differences among those major groups.

This can make subtler differences among individuals within one group difficult to see.

One way to investigate finer-scale structure is therefore to select a subset of individuals and repeat the PCA.

!!! important
    Repeating PCA on a subset of individuals is **not** equivalent to simply zooming in on those individuals in the original PCA.
    When the PCA is recalculated, the principal components themselves are recalculated to describe the major axes of genetic variation within the reduced dataset.

## 2.1.12. Interpreting PCA carefully

PCA is a descriptive method.

It identifies axes that summarise genetic variation, but it does not itself tell us the biological processes responsible for those patterns.

For example, separation along a principal component could reflect:

- geographical population structure;
- barriers to gene flow;
- isolation by distance;
- admixture;
- demographic history;
- relatedness;
- technical artefacts.

Interpretation therefore depends on combining the PCA with information about sampling, biology, and the structure of the dataset.

A particularly important point is that the PCs are **specific to the individuals and variants included in the analysis**.

PC1 from one PCA is therefore not necessarily biologically equivalent to PC1 from another PCA.
