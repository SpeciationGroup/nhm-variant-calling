# 1.4. Variant filtering

One could think that a VCF output by a caller represents a final, and undisputable, set of variants. Nothing could be further from the truth! In fact, variant calling is just the first step that is then proceeded by several stages of **variant filtering**. Variant filtering is an art - some would say, a dark art - and the best approach will depend on your chosen caller software, your dataset, and the purpose of your analysis. While a single 'correct approach' to variant calling almost never exists, it is good practice to make justifiable choices that are groudned in your data.

## (1.4.2) Hard filters

Hard filtering removes entire sites from the VCF. For example, some sites might be positioned in genomic regions that are biologically or technically problematic. Similalrly, some categories of sites, such as indels or multi-allelic SNPs, might simply fall outside the scope of your intended analysis. Note that different callers emit different sets of site annotations - compare the INFO header entries of the bcftools and GATK VCFs from previous worksheet (use `bcftools view` + `grep "##INFO"`) - so, consult the header descriptions, [vcf format specs](https://samtools.github.io/hts-specs/VCFv4.2.pdf), or the docs of your caller, if needed.

Below, we'll be working with the bcftools VCF.

### Step 1: Site categories

Some sites we are not interested in. For better or for worse, indels and multi-allelic SNPs are typically discarded on the outset of filtering. In general, most population genetic analyses are performed on **bialellic SNPs only**, in line of the assumptions of the [infinite sites model](https://en.wikipedia.org/wiki/Infinite_sites_model). Here, we follow this standard practice and narrow down our callset to biallelic SNPs while still keeping invariant sites:

```bash
bcftools view -Ou -M 2 -V indels,other,mnps ${VCF_PREFIX}.vcf.gz | bcftools filter -Oz -g 5:indel,other -o ${VCF_PREFIX}.step1.vcf.gz
```
(At this point, you should have seen a few `bcftools` commands, so we'll keep the explanations to minimum - if needed, please consult the [manual](https://samtools.github.io/bcftools/bcftools.html) or ask! Note that `-m2 -M2 -v snps` would be an idiomatic expression to retain biallelic SNPs only, but this would also remove invariant sites.)

We can immediately inspect how many sites were removed:

```bash
# Just print numbers to screen
bcftools view -H ${VCF_PREFIX}.vcf.gz | wc -l
bcftools view -H ${VCF_PREFIX}.step1.vcf.gz | wc -l

# Do some bash arithmetics - just for fun!
N_BEFORE=$(bcftools view -H ${VCF_PREFIX}.vcf.gz | wc -l)
echo $N_BEFORE
N_AFTER=$(bcftools view -H ${VCF_PREFIX}.step1.vcf.gz | wc -l)
echo $N_AFTER
awk -v b=$N_BEFORE -v a=$N_AFTER 'BEGIN{printf "Removed: %d sites (%.2f%%)\n", b-a, 100*(b-a)/b}'

# Shell function
report_removed() {
    local n_before=$(bcftools view -H "$1" | wc -l)
    local n_after=$(bcftools view -H "$2" | wc -l)
    awk -v b="$n_before" -v a="$n_after" \
        'BEGIN{printf "Before: %d\nAfter:  %d\nRemoved: %d sites (%.2f%%)\n", b, a, b-a, 100*(b-a)/b}'
}
```

!!! tip "Pipe"
    We've divided variant filtering into distinct steps for illustration purposes. In 'production code', however, everything could be 'piped' together and/or multiple conditions could be combined in individual bcftools command.

### Step 2: Depth

Variation in alignment depth is determined by a number of factors, including refernce completeness, GC-richness (e.g., [Ross et al., 2013](../papers/ross2013.pdf); [Browne et al., 2020](../papers/browne2020.pdf)) and repeat content ([Tjeng et al., 2025](../papers/tjeng2025.pdf)). Say a given reference region contains a repeat that is otherwise widely distributed in the genome - including in difficult-to-assemble regions that are NOT part of your reference. All these repetive reads will need to map somewhere...

In general, you should worry more about **excessive** depth than about low depth: while a shallow site is primarily less informative, a deep site can be actively misleading. Accordingly, we will remove sites where the depth exceeds 2.5 × the mean `INFO/DP`, with the factor chosen following a rule of thumb. To calculate the mean `INFO/DP`, find and uncomment a chunk of code in the plotting script!

```bash
# DP_MAX = 
bcftools filter -Oz -e "INFO/DP>${DP_MAX}" ${VCF_PREFIX}.step1.vcf.gz -o ${VCF_PREFIX}.step2.vcf.gz

# Inspect site loss 
N_BEFORE=$(bcftools view -H ${VCF_PREFIX}.step1.vcf.gz | wc -l)
echo $N_BEFORE
N_AFTER=$(bcftools view -H ${VCF_PREFIX}.step2.vcf.gz | wc -l)
echo $N_AFTER
awk -v b=$N_BEFORE -v a=$N_AFTER 'BEGIN{printf "Removed: %d sites (%.2f%%)\n", b-a, 100*(b-a)/b}'
```

!!! tip "Lower DP threshold"
    Setting a lower threshold on `INFO/DP` is more important in high-coverage samples.


### Steps 3-5: Phred-scaled scores

The next 3 scores are Phred-scaled, i.e., are logarithmically distributed with higher values meaning lower chance of error. Recall from a previous worksheet - 30 translates to 0.001 chance of error, etc.. The Phred-scaled scores are: 

- **QUAL** is an overall probability that a given genotype (variant or invariant) is correct. It is generally accepted that high-quality genotypes have QUAL>=30.
- **MQ** is the (arithmetic) mean mapping quality at a site. Again, 30 is a reasonable value.
- **SP** is a Phred-scaled p-value that one DNA strand is sequenced at a higher frequency than the other.

```bash
bcftools filter -Oz -e 'QUAL<30' ${VCF_PREFIX}.step3.vcf.gz -o ${VCF_PREFIX}.step4.vcf.gz
echo "QUAL filter: $(bcftools view -H ${VCF_PREFIX}.step4.vcf.gz | wc -l)"

bcftools filter -Oz -e 'MQ<30' ${VCF_PREFIX}.step2.vcf.gz -o ${VCF_PREFIX}.step3.vcf.gz
echo "MQ filter: $(bcftools view -H ${VCF_PREFIX}.step3.vcf.gz | wc -l)"

bcftools filter -Oz -e 'SP>3' ${VCF_PREFIX}.step4.vcf.gz -o ${VCF_PREFIX}.step5.vcf.gz
```

The MQ and SP scores are a good illustration of the between-caller differences in VCF output. Try fetching both from the headers of the respective VCFs ('bcftools view -h' + grep "MQ") - are they defined differently?

## (1.4.3) Soft filters

While hard filtering removes entire sites, soft filtering masks genotypes in selected individuals only, substituting them to misssing (`./.`). We filter by two annotations from the FORMAT field:

- **GQ** is Phred-scaled genotype quality in an individual
- **DP**

```bash
bcftools filter -Ou -S . -e 'FMT/GQ<20' ${VCF_PREFIX}.step5.vcf.gz \
    | bcftools filter -Oz -S . -e 'FMT/DP<5' -o ${VCF_PREFIX}.step6.vcf.gz
```
Note the -S... 

## (1.4.4) Missing data

As a final, additional hard filter, we remove the sites we high proportion of missing genotypes that we introduced ourselves.

```bash
bcftools filter -Oz -e 'F_MISSING>0.1' ${VCF_PREFIX}.step6.vcf.gz -o ${VCF_PREFIX}.final.vcf.gz
```
